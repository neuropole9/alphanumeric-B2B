# 5.0.11: variant editing and client PDF deployment

The `422 {"detail":"Unknown specification keys: source_url"}` comes from an imported catalogue provenance field being submitted as an editable specification. The edit form omits `source_url`; the backend preserves its stored value when specs are patched and continues to reject a new or modified unknown key. The PDF attached to this report was produced by the older renderer: it contains `Main Board Details`, `Room type`, `Area`, `Occupancy`, and long catalogue text on separate specification pages. The 5.0.11 renderer uses a room product table, a seven-column BOQ, and compact technical cards.

## Install on the existing Windows Docker Compose project

1. Back up PostgreSQL and uploaded media. Extract the ZIP and copy the application source into the SAME existing `D:\Arcot\AlphaNumeric-B2B` Compose project directory. Keep your `.env` and existing named volumes. Do not use `docker compose down -v` or import a development SQLite database.
2. In PowerShell: `cd D:\Arcot\AlphaNumeric-B2B` then `Test-Path .\.env`. If false, make a new `.env` from `.env.example` and enter your real secrets, company identity and bank details; preserve your existing `.env` when upgrading. Run `docker compose --env-file .\.env config`.
3. Rebuild and recreate the app: `docker compose --env-file .\.env up -d --build --force-recreate app`. This runs Alembic on startup. Check `docker compose --env-file .\.env logs --tail=100 app` for migration or boot errors.
4. Verify the version with `(Invoke-RestMethod 'http://localhost:8080/api/openapi.json').info.version`. It MUST return `5.0.11`. If it does not, check `docker compose --env-file .\.env ps`, the current Compose project directory, and the app build logs. Hard refresh the browser after the version check.
5. Retry editing the exact model. Verify that the save succeeds and that its pre-existing imported source remains in the database. Download a fresh project book and check that `Main Board Details`, `Room type`, `Occupancy`, and `Placement` are absent; rooms have tabular products; the BOQ columns are `Product Details`, `Model Number`, `Voltage`, `Quantity`, `Unit`, `Rate`, `Total`; and two normal technical product cards fit on one page. Do not compare against a previously downloaded PDF.

The previously attached `eyerdt Project Book.pdf` shows INR 0.00 throughout. An updated renderer cannot invent product prices: set the actual sell prices on the selected variants before sending a commercial PDF to a client. Confirm the exact model numbers and source `Input Voltage` values in your live PostgreSQL catalogue. The sample PDF in this release uses a sanitized test project; this environment cannot access your Windows Docker database or render the actual eyerdt project after deployment.
